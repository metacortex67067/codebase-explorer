# Benchmark Results

This file is regenerated by `python -m scripts.benchmark`. The numbers
below are placeholder targets and the column structure that the script
fills in -- run the benchmark on the same machine you plan to demo on
to get the real values.

## How to reproduce

```bash
source .venv/bin/activate
export ANTHROPIC_API_KEY=...      # required for the Q&A accuracy block
python -m scripts.benchmark
```

The script:
1. wipes `.benchmark_storage/`,
2. indexes `examples/demo_repo` end-to-end (ingestion + parse + chunk +
   embed + Chroma upsert + per-module LLM summary),
3. runs the 10 questions in `examples/qa_groundtruth.json` through the
   `/ask` flow,
4. overwrites this file with the measured numbers.

## Expected ranges

What is reasonable on a 2023 Apple-Silicon MacBook (M2/M3, 16 GB RAM)
with the demo repo (5 modules, ~150 LOC):

| Metric | Expected |
|---|---|
| Files indexed | 5 |
| Modules indexed | 5 |
| Chunks created | 15-20 |
| Index time | 2-5 s (first run includes embedder warmup ~1-3 s) |
| Vector store on disk | 50-200 KB |
| `ask` latency (median) | 1-3 s (LLM-bound, depends on Anthropic latency) |
| `ask` latency (p95) | 2-5 s |
| RAG citation accuracy | 0.7-1.0 |

If accuracy drops below 0.5 on the demo repo, suspect either:
- the embedder failed to load and you got a fallback that produces
  identical vectors (check stderr for sentence-transformers errors), or
- the LLM is misbehaving on JSON formatting -- inspect the raw response
  in `src/llm/client.py` debug output.

## Interpreting the per-question table

Each question is annotated with `expected` (modules that the correct
answer must cite) and `cited` (modules the RAG actually surfaced).
A question counts as "hit" if `expected ∩ cited` is non-empty -- a
deliberately lenient metric, because two different correct answers can
cite different but valid modules (e.g. "how is a todo created" might
land on `service.py` OR `models.py`).
